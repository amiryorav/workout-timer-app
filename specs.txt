## Overview
A simple browser-based interval timer for workouts. Configure exercises, rests, sets, repeats, and named workout profiles. Save/load workouts locally. Audio cues signal transitions and countdowns.

## Goals
- Run in any modern mobile browser (Android preferred)
- Fully configurable: workout profiles, exercise sequence, durations, rest periods, repeats
- Play sounds on transitions and final 3‑second countdown
- Prevent screen sleep during workouts
- No account needed—local config only; support JSON export/import

## Features
1. **Workout Management**
   - **Create** workouts with a custom name (e.g. "Upper Body", "Abs").
   - **Save** configurations to `localStorage` under a unique key.
   - **Load** or **Delete** saved workouts via UI, with delete confirmation dialog.
   - **Preview Mode**: view full sequence (warmup → main → cooldown) before starting.
   - **Export/Import** workout JSON for sharing or backup.
2. **Workout Definition**
   - Sections: **warmup**, **sequence**, **cooldown**, each a list of steps.
   - Step types: **Exercise** or **Rest**, custom names & durations.
   - Define **Sets** count and **breakBetweenSets** duration.
3. **Timer Flow**
   - Auto‑advance through phases and loop over sets.
   - Controls: **Play/Pause**, **Skip Forward/Backward**, **Restart**, with unsaved-abandon confirmation.
   - **Preview Mode** shows breakdown without starting timers.
4. **Audio Cues**
   - Distinct sounds for exercise start, rest start, last‑3s warning.
   - Toggle/adjust volume.
5. **Display**
   - Large, responsive timer digits—readable from across the room.
   - Phase name, countdown timer, set counter, progress bar.
   - **Dark Mode** toggle for low-light use.
6. **Non‑functional**
   - **Wake Lock API** to keep screen awake.
   - Responsive design with accessible font sizes and high contrast.
   - Lightweight (<200KB), offline-capable, no external CDN dependencies.

## UI Wireframes
1. **Home**: Dropdown/list of saved workouts, [New], [Import], [Delete] (with confirmation).
2. **Editor**: Form fields for name, sets, break; tables for warmup, sequence, cooldown; drag‑drop reorder; Preview & Save buttons.
3. **Player**: Full‑screen timer; responsive digits; phase name; controls; Dark Mode toggle.

## Tech Stack
- **TypeScript** (ES6 modules) for type safety with JSON model
- **HTML5/CSS3** (Flexbox/Grid, custom properties for theming)
- **JavaScript** Web APIs: Wake Lock API, Web Audio API
- **State Pattern**: simple Observable or Redux-lite to manage timer/UI state
- **localStorage** for persistence

## Additional Considerations

### Timer Accuracy and Drift Compensation
- Browser throttles `setTimeout`/`setInterval` in background or on mobile lock.
- Use `performance.now()` with `requestAnimationFrame` for active sessions; fallback to `setTimeout` when invisible.
- Listen to `document.visibilitychange` (via `document.visibilityState`) to detect tab switching or device sleep and adjust remaining time accordingly.
- Add unit tests in `timerController.test.ts` to simulate:
  - Normal 5s workout
  - Backgrounding/tab switch mid-phase
  - Device sleep/wake cycle

### Audio Cues and Mobile Restrictions
- Mobile browsers block audio until a user gesture; ensure playback is unlocked by requiring a tap on "Start" button before timer begins.
- Preload audio buffers on page load to reduce latency.
- Test on Android Chrome and iOS Safari after pause/resume and tab switches.
- Provide a silent-mode toggle to disable sounds for quiet environments.

### Responsive Design and Usability
- Use `clamp(min, preferred, max)` and `vw`/`rem` units for timer digits, but enforce a minimum font size to avoid clipping on very small screens.
- Ensure touch targets are at least 48×48 px (WCAG guidance) for controls.
- Test on screen widths from 320px to 1200px; adjust breakpoints as needed.
- Verify Dark Mode contrast ratios meet WCAG 4.5:1 for text against background.

### Accessibility Enhancements
- Test with screen readers (VoiceOver, TalkBack) so phase changes and countdowns are announced.
- Offer keyboard alternatives to drag‑and‑drop ("Move Up"/"Move Down" buttons) for sequence reordering.
- Add a "Skip to Content" link at top of both `index.html` and `editor.html` for keyboard users.

### User Feedback Mechanisms and Error Logging
- Include a feedback section (mailto: link or Google Form) in the Home screen for bug reports.
- Log critical errors (e.g., Wake Lock failure, JSON parse errors) via `console.error` with clear messages.

### Implementation Notes
- **Data Model**: Add optional `id: string` (UUID) to `Workout` for unambiguous CRUD keys in `localStorage`.
- **TimerController Hooks**: Document `onBeforeStart`, `onAfterComplete`, and drift-compensation logic in code comments for maintainability.
- **State Management**: Keep store simple; avoid full Redux unless state complexity grows.
- **Routing**: Consider SPA with `history.pushState` for faster navigation between Home, Editor, and Player UIs.
